# 東方 紅魔巡礼 GB v0.34 — ボス撃破・ボム背景切替・低速判定表示

## 変更

- BOSS MODEの最終撃破でも爆発を1個表示し、約1秒（VBlank 60回）待って次のボス／クリア画面へ進む。待機中は攻撃、タイマー、スコアを進めない。通常の各モード間の爆発・帰還・カットインは維持。
- BOSS MODEのクリア画像は、選択機体のエンディング末尾を使う。霊夢は`screen-clear`、魔理沙は`ending-marisa`。デバッグ得点のランキング除外も維持。
- 道中のボムは、実際のスクロール背景と陰陽玉／魔理沙スパークを交互に表示する。HUD、敵、自機、ショットの動作は継続する。ボス戦は既存の画像演出を維持。
- 森・湖・門・屋根・地下室（1、2、3、6、7面）の地形を再生成。各面40タイル、うち中央の視差用8タイル。左右32px＋中央56pxに全7面を統一。4、5面は既存素材の配置を修正。
- Bの低速中は実際の3×3px被弾判定の中心へ明暗の円を表示。判定サイズ自体は変更しない。モノクロGBでも自機の下に隠れないよう、左右2個のOAM部品を自機と同じ横位置に合わせて表示する。エディターの自機設定から有効・無効を変更できる。

## 道中ボムのVRAM配置

右HUDのある120px幅・動作継続型の画像ボムで使用する。

| 領域 | 内容 |
| --- | --- |
| `$8000–87FF` | ボム画像・HUD文字（符号なしタイル番号） |
| `$8800–8FFF` | スプライト画像を維持 |
| `$9000–97FF` | 道中背景・HUD文字（符号付きタイル番号） |
| BG `$9800` | 道中マップ |
| BG/Window `$9C00` | 左5列は右HUD用Window、残りにボムマップ |

ステージ読込時に両方を配置する。空白を含むマップ全体の初期化は一度だけ行い、ボムの絵は非空白の連続部分だけ書き込む。点滅時はLCDC・スクロールとGBCの画像用7パレットを切り替える。点滅のたびの画像・マップ転送と終了時のステージ再読込は不要。GBCの追加画像はVRAM bank 1へ置く。

ROMバンクを参照してパレットを用意する処理はVBlank前、表示レジスタとパレットポートへの書込はVBlank後に分けた。HUD用パレット0とOBJパレットは切り替えない。背景更新は常に`$9800/$9000`を指定し、現在表示中のボムへ誤って書き込まない。

魔理沙ビームはWindowマップの巻き戻りを避けるため、画面端だけ中心をx=12〜108に制限する。自機の移動範囲はx=8〜112のままなので、最端ではビーム画像が4px内側になる。ボムの全画面ダメージ判定は変わらない。

## 元画像と再現性

`projects/touhou-kouma/touhou-kouma-design/v34-backgrounds/`に、生成原画5枚、生成指示、出典パス、SHA-256、変換スクリプト、7面のプレビューを保存した。透明度を考慮して32×32へ縮小し、左右反転した地形と8枚の中央タイルから64×40のアトラスを作る。GBC用RGB画像とDMG用4階調画像は別々に保存し、公式コンパイル経路でタイル・パレットへ変換する。旧画像は削除していない。

## 検証

最終ROMのハッシュ、全試験結果、性能比較は`projects/touhou-kouma/touhou-kouma-design/qa-v34.json`へ記録する。

- `kouma-v34-rom.acceptance.mjs`: 製品ROMを実際のキー入力で操作。両機種・両機体の低速OAM、ボム中の画像常駐、背景切替、スクロール継続、終了後の復元、全7面の背景を確認。
- `right-hud-play.acceptance.mjs`: 右HUDの文字ピクセル、右端のスプライト、ボム、カットイン、ポーズ、ミス中のボスタイマーを確認。
- `boss-chain.acceptance.mjs --v34`: 短縮した2ボスの診断用ROM。両機種・両機体で爆発、待機中の時計停止、次戦・最終クリア、選択画像、コンティニュー、ランキング除外を確認。製品版全7ボスの通しクリア証拠とは区別する。
- `kouma-bomb-native.acceptance.mjs`: BGBでv33とv34を同じコントローラー入力により比較。ボム中の更新速度と開始・終了時の表示フレーム差を記録。
- `kouma-native-performance.mjs`: 通常道中と40発条件の終盤ボスを同じ入力で比較。

Emuliciousは接続できたがDAPの評価要求が`NullPointerException`で失敗し、実行結果の独立検証はできていない。DMG/GBC実機、音の主観的評価、長時間の展示動作は未確認。常時60fpsを保証する変更ではない。
