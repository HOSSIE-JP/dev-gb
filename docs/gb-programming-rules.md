# Game Boyプログラミング規約

## 適用範囲

本規約はGBDK-2020/SDCCを主対象とし、DMG互換ROMを基準にする。GBC拡張を使う場合も、共通コードとCGB専用処理の境界を明示する。細部は、固定されたツール版の公式GBDK資料、同梱ヘッダー・サンプル、ハードウェアの一次仕様を確認する。記憶や古いブログ記事だけを根拠にレジスタ値、ABI、コンパイラオプションを決めない。

## C言語とデータ型

- SDCC/GBDKが対象版で対応する言語機能だけを使う。PC向けコンパイラで通ることを根拠にしない。
- `uint8_t`、`int8_t`、`uint16_t` など、意図する幅と符号を型で表す。
- 8bit整数の整数昇格、符号比較、減算のアンダーフローを確認する。
- フレーム更新では不要な32bit演算、除算、剰余を避ける。
- 浮動小数点は原則使わず、必要なら固定小数点を使う。
- `malloc` / `free` などの動的メモリと再帰を使わない。
- 大きなローカル配列、構造体の値渡し、深い呼び出しを避ける。
- `printf` は初期疎通や診断に限定し、実ゲームではタイルベースの専用表示を使う。
- ISRとメインループで共有する値には必要な `volatile` を付ける。ただし `volatile` だけで複数バイト更新の原子性は得られないため、同期方法を別途決める。
- 未使用コードと未使用データを残さず、警告を隠さない。

## DMGメモリ構成の概略

代表的なCPUアドレス空間は次のとおり。MBC、CGBモード、各レジスタの例外は一次資料で確認する。

| 範囲 | 概要 | 注意点 |
| --- | --- | --- |
| `0000-3FFF` | ROMバンク0 | 割り込みベクタ、ヘッダー、固定コードを含む |
| `4000-7FFF` | 切替ROMバンク | MBC使用時は現在バンクに依存 |
| `8000-9FFF` | VRAM | LCD動作中はアクセス可能期間に制約 |
| `A000-BFFF` | 外部RAM | カートリッジとMBC、書込み許可に依存 |
| `C000-DFFF` | WRAM | CGBでは追加バンクあり |
| `E000-FDFF` | WRAMエコー | 通常は積極的に利用しない |
| `FE00-FE9F` | OAM | 40 OBJ分、アクセス可能期間に制約 |
| `FEA0-FEFF` | 使用禁止領域 | 読書きしない |
| `FF00-FF7F` | I/Oレジスタ | 副作用とタイミングを確認 |
| `FF80-FFFE` | HRAM | 小容量、高速処理やDMA中処理に利用可能 |
| `FFFF` | 割り込み許可 | `IE` レジスタ |

数値範囲をハードコードするときは、用途を示す名前付き定数と型を使う。ポインタで直接I/Oを触る前に、GBDKが提供するレジスタ定義または安全なAPIがないか確認する。

## VBlankとフレーム

- メインループは `vsync()` または確認済みのVBlank同期手段を使い、無制限に回さない。
- 入力は原則1フレームに一度読み、現在状態と前フレーム状態から押下エッジを作る。
- ゲームロジックと描画準備はVBlank外で行い、VBlank中の仕事を短く予測可能にする。
- 1回のVBlankで転送できる量を越える場合は分割、dirty更新、事前ロードを使う。
- LCDを無効化して大量転送する場合は、画面初期化やシーン切替など限定された箇所へ閉じ込める。
- VBlank待機はLCDや割り込みの状態と組み合わせによって停止し得るため、初期化順を確認する。

## LCD、VRAM、OAM

- LCDが有効な間のVRAM/OAM更新可能タイミングを守る。
- GBDKのタイル、背景、スプライトAPIを優先し、直接書込みが必要な場合は責務をプラットフォーム層へ限定する。
- OAM転送はシャドウOAMなど、固定版GBDKが推奨する方法を使う。
- シーン変更時は、不要なOBJ、スクロール、ウィンドウ位置、パレット状態を明示的に初期化する。
- STAT/LYを利用する走査線効果は、割り込み時間と実機差を計測してから導入する。
- DMA中のCPU実行制約を考慮し、確認済みライブラリ経路を無視して独自DMAを追加しない。

## スプライト制限

- OAMに登録できるOBJは40個までである。
- 1走査線に表示できるOBJは10個までで、超過時は欠ける。メタスプライトの部品数も個別に数える。
- 弾、敵、爆発、UIカーソルを含めた最大同時数を定数として管理する。
- 非表示OBJを画面外へ移動し、前フレームの残像を残さない。
- 優先順位とOAM順序への依存はDMGとCGBで確認する。
- 8x16モードではタイル番号の下位ビットや上下ペアの扱いを一次資料で確認する。

`star-caravan` では、最悪時の自機、敵、ボス、双方の弾、爆発を同時に数える。オブジェクトプールの上限と描画可能数は別概念として扱い、描画を省略しても当たり判定の整合性を壊さない。

## タイルとパレット

- タイルは8x8ピクセル、2bppを基本単位とする。
- 背景、ウィンドウ、OBJで、タイル番号の所有範囲と寿命を決める。
- 同じタイルを再利用し、VRAMとROM使用量を抑える。
- DMGでは4階調、OBJでは透明色を考慮してデザインする。
- CGBパレットはCGB実行時だけ設定し、DMG向け濃淡の可読性を維持する。
- DMG/GBC共通ROMでは、CGB専用VRAMバンクや属性を書き込むコードを機種判定なしで実行しない。

## Joypad

- joypadのビットマスクはGBDKの定義を使い、数値を複製しない。
- 現在状態 `current` と前状態 `previous` から `pressed = current & ~previous` を求め、決定やポーズはエッジで処理する。
- 方向キーの同時押し、A/B同時押し、押しっぱなし、シーン遷移直後を定義する。
- 連射はフレームカウンタで決定的に制御し、ホスト時刻へ依存しない。
- ポーズ中はタイマー、敵、弾、乱数の更新を止める範囲を明確にする。

## 割り込み

- ISRは短くし、フラグ更新、カウンタ、必要最小限の転送に限定する。
- ISRから一般的なゲームロジック、重い描画、可変時間処理を呼ばない。
- 割り込み優先関係と有効化順を明示する。
- 共有する16bit以上の値は途中状態を読まないよう、短い割り込み禁止区間や二重読取りなどの方針を定める。
- ISRから呼ぶ関数がバンク切替を必要としないか、再入可能性に問題がないか確認する。
- デバッグ用ログをISRへ追加してタイミングを壊さない。

## ROMバンキング

32KiBを越えるまではMBCなしの単純なROMを優先する。バンキングを導入するときは、採用するMBC、ROM/RAMサイズ、バンク割当てを `project.json` と設計文書に記録する。

- バンク切替APIは一か所へ集約する。
- バンクをまたぐ通常ポインタや関数ポインタを無警戒に保持しない。
- 呼出し元と呼出し先が期待する現在バンクを明示する。
- ISRからバンク済み関数を呼ぶ場合の安全性を確認する。
- 固定バンクには割り込み、バンク管理、頻出コードを優先して置く。
- バンク割当て変更後は `.map` と実行時のブレークポイントで確認する。

GBDKのバンク属性や呼出し規約は版に依存し得るため、 [`config/tools.lock.json`](../config/tools.lock.json) で固定した版の資料を使う。RGBDSのセクション／バンク指定と混同しない。

## SRAM

SRAM保存を導入する場合は、カートリッジ種別とRAMサイズをヘッダー設定に一致させる。

- 書込み時だけRAMを有効化し、完了後に無効化する。
- バンク切替を保存層へ閉じ込める。
- マジック値、形式バージョン、長さ、チェック値を持たせる。
- 初回起動、破損、旧版データを安全に初期化または移行する。
- 複数スロットや世代を使い、電源断途中でも可能な限り直前データを残す。
- 毎フレーム書き込まず、明確な保存時点を設ける。

現行の `star-caravan` の上位5スコアはRAMだけに保持し、リセットまたは電源断で消去する。SRAMは使用しない。

## 固定小数点

速度や加速度に小数精度が必要な場合は固定小数点を使う。例えば位置を8.8形式で持つなら、上位8bitを画面座標、下位8bitを小数部として扱える。

- ビット数とスケールを型名またはコメントで明示する。
- 乗算前の型幅と最大値を計算し、中間値のオーバーフローを防ぐ。
- 負数の右シフトなど、処理系依存の挙動へ無自覚に依存しない。
- 描画座標への丸め方を統一する。
- 衝突判定が描画座標と内部座標のどちらを使うか決める。

単純な一定速移動で十分なら、固定小数点を導入せず8bit/16bit整数を使う。

## 実機とエミュレーターでの検証

最低限、次の順で確認する。

1. `doctor.cmd` でローカル環境を検査する。
2. DebugとReleaseの両方をビルドする。
3. BGBで短い反復とタイミングを確認する。
4. Emuliciousでシンボル、VRAM、OAM、メモリ、割り込みを確認する。
5. DMGモードとCGBモードで同じゲーム結果になることを確認する。
6. 可能ならDMG、CGBまたは互換機とフラッシュカートで確認する。

実機では特に、電源投入直後の未初期化状態、液晶でのコントラスト、入力感、スプライト欠け、音量、長時間動作を確認する。エミュレーターの許容する未定義・不正なアクセスが実機でも動くとは限らない。

## 完了前チェック

変更を完了したとみなす前に、少なくとも次を実行する。

```bat
doctor.cmd
clean.cmd star-caravan
build.cmd star-caravan -Configuration Debug
build.cmd star-caravan -Configuration Release
test.cmd
```

実行できない項目は、理由、未確認範囲、利用者が実行すべき具体的なコマンドを報告する。
