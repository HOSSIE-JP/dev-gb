# 東方 紅魔巡礼 GB v0.35 — 固有背景と陰陽玉の欠け修正

## 変更

- 6面の紅魔館を、赤い石壁・屋根・煉瓦の配色へ変更。
- 中央は全7面で異なる模様にした。1面は旧森林、2面は旧水面、3面は旧石床、4面は菱形模様、5面はアーチ、6面は新しい赤煉瓦、7面は旧地下の模様。4・5面の元データは変更していない。
- 2面の左右を、独立した氷塊の列から、連続した氷面と割れ目のタイルへ変更。中央の波模様を復元し、左右の地形と中央の水面が異なる速度で流れる。
- 左右32px、中央56px、右HUD40pxは維持。差し替えた各地形は40タイル、視差で更新する中央は8タイルのまま。

原画、生成指示、元画像のハッシュ、取り込みスクリプト、プレビューは `projects/touhou-kouma/touhou-kouma-design/v35-backgrounds/`。編集用画像は `assets-src/images/map-*-v35*.png` に保存した。旧画像は保持している。

## ボム欠けの原因と修正

VRAMの不足ではなかった。道中ボムの事前ロードが、モノクロ版の空白タイルを使ってカラー版のマップまで省略していた。GBとGBCの元画像は独立しているため、モノクロで空白でもカラーでは絵があるセルを消してしまっていた。

使用する機種のマップを15セルずつ連続して一度だけロードするよう修正した。陰陽玉の画像サイズは維持。点滅中の画像・マップ再転送は引き続きゼロで、常駐RAMも増えていない。

製品ROMを入力操作してボムを発動し、VRAM・マップ属性・パレットから復元した左120×144pxの17,280ピクセルを元画像と比較した。スプライトはこの比較から除外している。

| 条件 | v34の不一致ピクセル | v35 |
| --- | ---: | ---: |
| GBC・道中 | 128（8×8タイル2枚） | 0 |
| GBC・ボス | 0 | 0 |
| GB・道中 | 0 | 0 |
| GB・ボス | 0 | 0 |

## 検証方法

- `kouma-bomb-art.acceptance.mjs`: 上記4条件の製品ROMと元画像の全ピクセル比較。
- `kouma-backgrounds.acceptance.mjs`: 全7面×GB/GBCをメニューから開始。カメラ進行、中央のVRAMパターン変化、右HUD固定を確認。
- `kouma-v34-rom.acceptance.mjs`: 両機体・両機種のボム背景切替、スクロール継続、常駐スプライト維持、終了後復元、道中／ボス低速マーカー。
- `right-hud-play.acceptance.mjs`: HUD文字・右端・ボム・ポーズ・カットイン・被弾中のタイマーを回帰確認。
- `kouma-bomb-native.acceptance.mjs`、`kouma-native-performance.mjs`: BGBで同一操作を再生し、表示フレームとゲーム更新数を測定。測定値と入力ハッシュは `qa-v35.json`。
- BGBの完成フレームで、2面の氷と水面、6面の赤い背景、霊夢ボムの修正前後を目視確認。

原画レベルの色確認に加え、GBとGBCの中央模様が7種類とも異なること、縦方向にずらすと模様が変わることを回帰テストで確認した。旧水面は意図した2階調のため、当初の「3色以上」テストは不適切と判断し、2色以上と縦方向の変化、ROMでの実際の動作を検証する条件に修正した。

Emuliciousは今回のROMでもDAP評価が `NullPointerException` で失敗し、独立した実行確認ができていない。DMG/GBC実機、主観的な音の確認、長時間展示は未確認。今回の修正は常時60fpsを保証するものではない。
