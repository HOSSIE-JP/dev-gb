# Caravan GBC専用実行系

`assets-src/game.json` の `hardware: "gbc"` が専用実行系を選ぶ。未設定または `"dual"` は従来のGB/GBC実行系。東方のみ専用化し、セーブID・スコア形式・生成上限・処理順は変えない。

## メモリと割り込み

| WRAM | 予約範囲・用途 |
|---|---|
| 固定 | 共通状態、音声、割り込み、shadow OAM。データは`$CC00`未満 |
| 固定スタック | `$CC00..$CFFF`の最低1KiB。初期SP=`$D000` |
| 1 | `$D000..$DD51`。21個の敵・ボス・演出・アイテム実体、39論理スロット、6バイト弾ヘッダー、弾SoA、判定・経路・アニメーションキャッシュ |
| 2 | `$D000..$DF23`。64個分のBG弾SoA、セルマスク、合成タイル、2面のマップ、変更候補行 |
| 3 | `$D000..$D81F`。最大2KiBの視差画像と新規行の転送パケット |
| 4 | `$D000`から779バイト。動画・PCM作業域。動画中はこのバンクに固定 |
| 5〜7 | 未使用 |

ゲーム更新・スプライト描画はバンク1で行う。BG公開関数はバンク2へ切り替え、呼出元のSVBKを復元する。道中の準備／転送もバンク3をまとめて選択する。通常の割り込みは固定WRAMだけを参照する。動画のタイマー割り込みだけは、再生中に固定されるバンク4を参照する。動画終了ではタイマー解除後にバンク1へ戻す。

絶対配置はC側の`CE_WRAM`／`__at`とリンカーの`.STACK`で指定する。ビルドは実際のリンク結果の固定領域上限・主要アドレス・スタック位置を検査する。予約サイズは隙間を含む。新たに配列を増やす際は、C側の配置と`editor/src/node/cgb-layout.ts`を同時に更新する。

## 更新と描画

- 論理39スロットの順序、OAM予約、衝突と加点順を維持。弾は25バイトの敵構造体を所有しない。敵・演出・アイテムの実体を共有する21枠は、種類別の既存上限で制御する。
- ビルド時にアニメーションフレームごとのOAMテンプレートをROMバンク3へ生成する。実行時は原点込みオフセットに座標を加え、従来と同じ順序でOAMへ出力する。不可視部分による新たな生成許可や動的配分は行わない。
- 区分直線経路は現在の区間を記憶し、区間内では量子化済み速度を加算する。境界・折返し・寿命カウンターの周回では元の計算へ戻る。滑らかな経路・波形は既存処理を使用する。
- レーザーは更新済みの敵判定矩形を再利用する。負のQ4座標は従来同様、ゼロ方向へ丸める。
- 道中は新規15列の行と変更された視差位相を準備し、VBlankでGDMA転送する。既存のHUD変更検出を維持する。
- BG弾は従来の2×2ドットと単独／二重配置辞書を維持する。表裏それぞれに前回使用行を保持し、現フレームの使用行・消去行・HUD変更行を更新する。これは保守的な行単位の差分で、全セルの同値判定による完全な最小差分ではない。
- 合成タイルは表裏別領域へ置く。表示中のマップの合成タイルを上書きしない。初期HUDの全行更新は連続GDMA、通常更新は変更候補行のGDMAを使う。HBlank DMAは使用しない。

## VRAMと画像

通常OBJの予約は128タイル以内。BG弾幕ではHUD、136種の辞書（HUDが大きい場合16種）、表裏の合成タイルを255タイル以内に収める。ボムは既存のOBJ予約`128..255`を避ける配置・復元処理を維持する。カットインと動画の全画面表示後にはゲーム用配置を再ロードする。

カラー元画像・DMG元画像は編集データに残す。専用ROMでは、独立カラー画像がある画面・背景・スプライトと動画のDMG専用ペイロードを出力しない。HUD・文字・共通画像データは引き続き使用する。ROMサイズは容量境界で丸められるため、ペイロード削減と最終ROM容量は一致しない。

## 計測上の注意

`gbc-runtime-parity.mjs`は同じ論理更新で状態、OAM、VRAMから復元したBG、OBJタイル、両パレットを比較する。PPU走査位置の異なる瞬間のフレームバッファを同一画面と扱わない。論理境界のPPUフレーム番号の差は診断値であり、そのまま描画締切超過数とはしない。

実時間の主測定はBGBの公開トレースとVBlankカウンター。`gbc-runtime-native-load.mjs`は40発専用試験の公開直後を測る。`cpu-profile.mjs`はCPU命令位置のサンプリングで、内訳の平均・p95・最大は推定値であり、関数を計装した厳密な呼出時間ではない。

性能合格は平均値では判断しない。通常区間・40発試験・ボム中の1表示フレーム1更新とVRAM安全性をそれぞれ評価する。実機・聴感・Emuliciousの確認はBGB／Boytaceanの結果とは別に記録する。

仕様確認: [Pan Docs CGB registers / DMA / WRAM](https://raw.githubusercontent.com/gbdev/pandocs/master/src/CGB_Registers.md)、[OAM](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md)。
