# 東方 紅魔巡礼 GB v0.19

ボム表示中の敵へのダメージ、キャラクター選択の見出し、タイトルのステージセレクトを追加しました。

## 操作と変更

- タイトルで上下を押すと `START` / `STAGE SELECT` を選択します。`STAGE SELECT` 上で左右を押すと01〜07を循環し、A / STARTでキャラクター選択へ進みます。通常のSTARTは1面から開始します。
- キャラクター選択で左右を押すと霊夢／魔理沙を変更、A / STARTで開始、Bでタイトルへ戻ります。Bで戻ってもメニュー項目とステージ番号を保持します。両方の立ち絵に「キャラクター選択」を表示します。
- ボム発動時だけでなく、表示中に新しく現れた敵、画面端から進入した敵にも30ダメージを与えます。同じ敵にはボム1発につき1回です。次のボムでは再びダメージを与えられます。これにより既存のボスHP・ボム威力を維持しながら、途中参加の雑魚も倒せます。
- ボムの消費数・48更新の演出時間・陰陽玉／魔理沙スパークの画像は従来どおりです。明滅の暗いフレームも効果時間に含みます。
- 選択した面をクリアすると、通常のステージ順で先へ進みます。コンティニューは現在の面の先頭へ戻ります。SELECTボタンによるランキング表示も利用できます。

## エディター

「画面・HUD」→「タイトル」の `START／STAGE SELECTメニュー（下4行）` で有効化します。下4行はメニュー専用となり、その範囲の背景と従来の文字表示を置き換えます。メニュー項目とステージを中央のプレビューで確認できます。

「自機」の `「キャラクター選択」の見出し` で選択画像の上端に見出しを表示します。機体別プレビューにも反映されます。どちらもビルドせずに編集・保存できます。既存プロジェクトでは両設定とも省略時に無効です。

編集元は `projects/touhou-kouma/assets-src/game.json` とPNGです。PNGを直接加工せず、既存フォントによるUI表示をコンパイラーとプレビューで共有しています。

## 実装

進行するボムの有効期間中、敵移動の後・通常弾の衝突判定の前に対象を確認します。敵の画像矩形が画面と交差した時点でダメージを与えます。39個の固定エンティティ枠に対する5バイトのビット集合で適用済みの敵を記録し、枠の再利用時にそのビットを解除します。新しいボムを使うと集合を初期化します。ボスの無敵は維持します。

タイトルのカーソルとステージ番号は2バイトです。変更時に必要な4タイルだけ更新し、画像全体の再転送は行いません。合計の追加WRAMは7バイト、静的WRAM＋shadow OAMは **7,126 / 8,192バイト**。従来と同じ1,024バイト以上のスタック予約を確保しています。

## 検証

Debug / Releaseは同一の1MiB ROMです。標準 **130テスト成功・スキップ0**、型チェック、doctor、hello-gb Debug、star-caravan Debug / Releaseを確認しました。

ROM: `projects/touhou-kouma/build/Release/touhou-kouma-v19.gb`

SHA-256: `ce938c9d0b255e1ca5cc2265c534eea4e25db17f7c2d3780a1505ed3425e3aab`

結果と証跡は `touhou-kouma-design/qa-v19.json` と `qa-v19/` に保存しています。

- 通常ROM：DMG/CGB × 2機体 × 7ステージの28通りを通常入力で開始。タイトルと選択画像はROMのVRAMから全画素を照合しました。折返し・ボタン押しっぱなし・Bで取消し・通常START・ランキング表示も確認しました。
- 通常ROM：道中／ボス × DMG/CGB × 2機体の8ケースで画像ボム中の移動、射撃、敵移動、弾消去、ボム後の復帰を確認しました。
- 通常ROM：ステージセレクトから3面へ入り、DMG/CGB × 2機体で残機5→0、待ち時間、ランキングのSRAM保存・再起動、同じ面・機体でのコンティニューを確認しました。
- 入場検証ROM：HP60の敵を上下左右から進入させ、各30ダメージで止まることを確認。表示途中のHP10雑魚2波の撃破・得点・同じ枠の再利用、表示後の敵が無傷なことを4ケースで確認しました。自機操作以外でROMのRAMは変更していません。
- BGB：DMG/CGB × 2機体で、7面選択・取消し・開始を4ケース、既存画像ボム2発と48更新の継続動作を4ケース確認しました。
- 形態移行検証ROM：HP20のボス2形態を使い、ボム終了後の形態変更・カットイン・勝利会話・集計の順序を4ケースで確認しました。
- 実Electron：見出しとメニューの有効／無効、2機体と7ステージのプレビュー、保存・再読込を操作しました。会話設定とボム設定も維持されています。テスト用プロジェクトのビルドは行っていません。

## 残る制約

画像ボムの開始・終了には既存のBG転送待ちが残ります。今回の変更は60fps達成の追加最適化ではありません。前版の40発負荷試験はCGB平均約55更新/秒で、詳細は [v0.18報告](touhou-kouma-v18.md) にあります。

実機、通常条件での全編クリア、人による音・操作感の評価は未確認です。Emuliciousは接続後のDAP `evaluate` が `NullPointerException` で失敗したため、実行検証に数えていません。
