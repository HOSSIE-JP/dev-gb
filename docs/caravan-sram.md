# スコアのSRAM保存

共通Caravanランタイムは、ゲーム終了時に上位5件へ入ったスコアを保存します。NOVA SPEARとSTAR CARAVANの両方が対象です。毎フレームや撃破ごとの書込みは行いません。

ROMヘッダーはMBC5＋RAM＋バッテリー（0x147＝0x1B）、8KiB RAM（0x149＝0x02）です。32KiB作品もSRAMのためにMBC5を使用します。外部エミュレーターのバッテリー保存を有効にし、通常はROMと対応する`.sav`を保管してください。実機では対応するカートリッジ／フラッシュカートと正常な保存機構が必要です。

## 記録形式 v1

RAM bank 0の0xA000と0xA020に各32バイトを予約し、各スロットの先頭20バイトを使用します。16ビット整数はリトルエンディアンです。

| オフセット | 内容 |
| --- | --- |
| 0 | コミット印 0xA5 |
| 1 | 形式バージョン 1 |
| 2–5 | 作品名から生成する32ビットFNV-1a識別子（上位バイトから格納） |
| 6–7 | 世代番号 |
| 8–17 | 降順の16ビットスコア5件 |
| 18–19 | バイト1–17のCRC16-CCITT、初期値0xFFFF、多項式0x1021 |
| 20–31 | 未使用 |

起動時に両スロットを検証します。世代差を16ビット循環で比較し、新しい有効記録を選択します。片方が破損していればもう片方へ戻り、両方が無効なら全件0点で開始します。作品識別子・形式・降順も検査します。作品名の変更は別作品として扱われます。

保存時は古い方のコミット印を無効化し、本文とCRCを書いた後、コミット印を最後に書きます。読み戻し検証に成功してから現在の世代を進めます。直前の有効スロットは上書きしません。RAMの有効化・bank 0選択・無効化を保存層に閉じ込めます。任意の電気的故障や両スロット同時破損まで防ぐ保証ではありません。

## 内蔵ROMプレイヤー

SRAMを作品ごとの`caravan.sram.v1.<作品名>`へ16進文字列で保持します。同じ作品ならDebug/Release、DMG/CGB、再ビルドで共有します。約60表示フレームごとに変更を確認し、変更がある場合だけ保存します。再読込、作品切替、非表示、終了時にも退避します。読込時はSRAMサイズと文字列形式を検査し、不正な保存内容は上書きせずエラーを表示します。保存容量不足なども表示します。

アプリのデータ消去、ブラウザーのサイトデータ削除、保存直前の強制終了ではデータを失う可能性があります。内蔵プレイヤーの保存は外部エミュレーターの`.sav`とは別です。

## 検証

`editor/tests/save.acceptance.mjs`は実際のGBDK ROMで得点を獲得し、SRAMを新しいDMG/CGBインスタンスへ渡して再起動します。2回のランキング更新、全20段階の未コミット書込み、片側／両側破損、世代番号の65535→0、別作品の記録を検査します。同じ短縮マップでスクロールの循環も確認します。

追加のChromium実操作では、短縮ゲームで1500点を獲得→保存→ページ再読込→スコアボード表示まで確認しました。Windows版Electronと物理カートリッジでの検証は未実施です。
