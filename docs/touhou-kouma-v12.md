チルノと美鈴の横弾はY=88/104/120、咲夜はY=80/96/112/128へ移しました。160×144画面の上端がY=0です。発生位置の変更だけでなく、横弾が実際にX=72〜88の中央域を下半分の高さで横切ることをDMG/CGBの弾配列から確認しました。弾速・発射間隔・同時弾上限は増やしていません。

## 処理負荷への対策と実測

同じ新配置を使い、最適化前後を比較しました。ROMのPCを周期に偏らない間隔で読むサンプリングでは、敵と自機弾の衝突検査、敵更新、波状移動が主な処理負荷でした。次の3点を変更しています。

1. 衝突していない弾は座標比較で先に除外し、敵情報の読み直しを減らす。命中時には、途中で消去・再利用された枠や無敵ボスを従来どおり確認する。
2. 攻撃を持たない敵では発射予定時刻の参照と攻撃ループを省く。
3. 周期128の波状移動は、直線成分を加算し、8更新ごとの波形の差分だけを加える。毎更新の掛け算を減らし、軌道と速度を維持する。

GBCで自機を左端に置いて連射し、多くの敵を倒さず残す負荷試験です。全7道中の元のイベント時刻・敵・武器・マップを使い、各道中から最初と最後の64更新を除いてPPUフレーム数を測りました。描画フレームを飛ばして高速化した値ではありません。

|---|---:|---:|

| 2 | 53.14 → 57.22 | 54.13 → 58.33 |
| 3 | 57.62 → 58.44 | 57.79 → 58.92 |
| 4 | 56.16 → 58.18 | 57.32 → 58.73 |
| 5 | 56.38 → 58.27 | 56.67 → 58.32 |

GBCの道中は連射時56.31〜59.40更新/秒。敵3体以上の区間だけでは約54〜59更新/秒、最大3表示フレームかかる更新も残ります。非射撃では概ね59更新/秒以上です。常時60fps達成とはしていません。DMGの道中は約32〜44更新/秒で、こちらも処理落ちが残ります。

全21ボス弾幕も再計測し、GBCは58.40〜59.73更新/秒、最大40発でした。ボス試験では段階を検証用に強制進行しており、通常条件での全ボス撃破を意味しません。

## 検証結果と保存先

- doctor（警告0）、hello-gbのclean/Debug、test.cmd 80件、star-caravanとtouhou-koumaのDebug/Releaseが成功。
- 全7道中×2機体×DMG/CGB×射撃有無を確認。射撃しない試験では612体すべての出現を数え、出現抜け0。最大OAM38/40、画面内の走査線最大6/10。
- 通常ROMでは2機体×DMG/CGBで3回のラッシュを通り、最初のボス前会話へ到達。霊夢は39回の得点増加・うち21回が前の撃破から30更新以内、魔理沙は54回・うち30回。残機はそれぞれ2、3。複数体同時撃破は1得点イベントとして数えています。
- 最適化前後の最初の2道中を同一入力で比較。非射撃・連射の計9,448更新でゲーム状態、敵・弾データ、実OAMが一致。
- 波状移動の独立した式との照合をDMG/CGBで実施。4設定×全65,536カウンター値と折り返しが一致。負の速度、16bit座標の折り返し、振幅255も含む。
- BGB 1.6.6でも道中試験ROMを入力デモで操作し、最初の2道中の密集を確認。霊夢連射で59.485／57.102更新/秒。エミュレーター間のタイミング差はあるものの、実行と密度を別実装でも確認。
- EmuliciousはDAP初期化まで成功し、ROM起動応答が60秒でタイムアウト。実行できた検証には含めない。
- 既存画像75枚はバイト単位で一致。機体・専用ボム・機体別会話・ボスHP・カットイン・集計待ち等も比較し、今回の配置変更以外を保持。原画の追加・差替えはなし。
- 全撃破・残機5・ノーミス想定の配置上の最大得点は63,390で、16bitの65,535を超えないことを確認。

全道中の負荷試験は、ボスイベントを道中終了に置き換え、会話・画面転換演出を省き、残機9・初期無敵1024更新にした使い捨てROMです。エンジンの計測用改造や実行時RAM書き換えはありません。通常難易度での全編クリア、DMG/CGB実機、人による操作感・音・難易度の評価は未確認です。
