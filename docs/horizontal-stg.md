# 横スクロール・取得アイテム・破壊BG

Caravan Editorの共通GBDKエンジンと即時プレビューに同じ機能を追加しています。「新規作品」のSIDE CARAVANを選ぶと、横スクロール向けの素材・配置・強化設定を持つ独立作品を作れます。ゲーム本体の正本は`assets-src/game.json`と`assets-src/images/*.png`です。

## ステージと射撃

ステージのスクロール軸を横にすると、右へ進み、背景が左へ流れます。横マップは幅20〜512タイル、高さ18タイル。縦は従来の幅20、高さ18〜512です。長さ512タイルのループも扱います。マップ寸法の変更では共通領域のタイル・壁を保持し、範囲外になった破壊物を除きます。Undoで戻せます。

イベント位置は画面座標です。編隊の間隔Xと間隔Y、時差を組み合わせて、横一列・縦一列・斜めの編隊を作れます。移動の振動軸は波・往復の揺れる方向を指定します。弾の角度は上0度、右90度、下180度、左270度です。

武器の発射点は素材の発射点を使います。`emitterOffsets`を指定した武器では、自機・敵の原点からの相対座標が優先されます。2連は2発射点、3／5方向は1発射点とfanの弾数を組み合わせます。発射点とfan弾数は掛け算になることに注意してください。

斉射単位の確保を有効にすると、弾枠が足りないときはその斉射全体を見送ります。5方向の片側だけが発射されることを防ぎます。自弾数の設定を増やしても、全体39エンティティとOAM40のハード上限は変わりません。

## アイテムと強化

「アイテム」で8×8の素材、移動、有効時間、取得効果を設定します。取得効果は複数組み合わせられます。

| 効果 | 内容 |
| --- | --- |
| shot | ショットを指定段階分強化 |
| speed | 速度を指定段階分強化 |
| bomb | ボム在庫を加算 |
| life | 残機を加算 |
| score | スコアを加算 |

自機の強化表には初期段階を含め、ショットの武器IDと速度を順番に並べます。ミス時の規則はそれぞれ維持・1段階低下・初期化から選べます。強化状態はステージ間で保持され、新規プレイでは初期段階になります。HUDの`shotLevel`と`speedLevel`は初期段階を1として表示します。

取得したアイテムは一度だけ適用されます。強化・ボム・残機は各上限で止まり、上限時にもアイテムは消えます。同じアイテムに得点効果があれば適用します。スコアは65535で飽和し、従来のSRAMランキング形式を使います。

ステージのitemイベント、敵のドロップ、破壊物のドロップから出現できます。敵・BGの撃破地点で出現し、設定した画面上の移動を始めます。自機が無敵でも取得できますが、復帰待ち中には取得しません。アイテムは自機にダメージを与えず、ショットでは消えません。

アイテムを定義した作品では共通プールから最大4個分を予約します。5個目の同時出現は見送りとして数えます。プレビューの診断を見て、寿命や出現時刻・ドロップを調整してください。

ボムの入力は従来のA+B同時押し、またはB単独を選べます。B単独ではAがショット、Bは押した瞬間に1回だけ消費します。押し続けても連続消費せず、離して押し直す必要があります。

## 破壊物の配置

ステージの破壊物の種類に名前、4枚のBGタイル、HP、得点、接触判定、任意のドロップを設定します。破壊レイヤーを選び、16×16のスタンプとして配置・消去します。普通の地形タイルは下地として保持します。

- 物体は16×16ピクセル固定、16ピクセルのグリッドに揃えます。重複・マップ外は配置できません。
- 1面最大512個、HP1〜15です。4枚のタイルは1つのHPと得点を共有します。
- 自弾が当たるとHPが減り、最初に0になったときだけ加点・ドロップが発生します。
- 接触判定を無効にすると自機は上空を通過できます。有効なら破壊するまで接触で被弾します。
- 破壊後は元の地形が見えます。ミス、スクロールの周回、ボム・カットイン後の背景復帰でも再生しません。ステージへの新しい進入や新規プレイでは初期化します。
- ボムの背景破壊を有効にすると、画面内に一部でも重なる物体を破壊し、通常の得点とドロップを発生させます。

BG物体は敵・スプライト枠を使いません。HPは512個で256バイト、描画更新待ちは64バイト。ROM上の16ピクセルセル索引を使い、自弾付近の物体だけを調べます。通常の破壊結果の転送は1更新最大8タイルで、残りは次回以降に反映します。混雑中は判定が消えたあと、見た目の消去が少し遅れる場合があります。

## 互換性と検証

追加設定を省略したschemaVersion1作品は従来の縦スクロール、自弾6発、素材発射点、A+Bボムを使います。既存の`scrollDown`は縦スクロール専用です。編集用マップは引き続き行順で保存し、横スクロールの列順データはコンパイラが生成します。

`npm run test:core`でデータとプレビュー、`npm run test:rom`でGBDKによるDMG／CGB実ROMの照合を実行します。横スクロールの実Electron検査はリポジトリのルートで`.tools\node\node.exe editor\tests\horizontal-ui-run.mjs`を実行してください。通常のゲームを遊ぶ確認と、短縮・高負荷のテスト用作品は別の検証です。

エディターディレクトリーの`npm run test:horizontal-ui`でも同じUI検査を実行できます。SIDE CARAVANのDebug ROMをビルドしたあと、`npm run test:side`で通常ROMの道中・ボス通し試験、`npm run test:side:native`でBGBの入力試験を実行できます。通し試験はROM・編集データ・ビルド記録の一致を検査し、ROMやWRAMを変更せず、通常入力だけで進行します。
