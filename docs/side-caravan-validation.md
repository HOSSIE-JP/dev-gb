# 横スクロールSTGとSIDE CARAVAN 実装・検証報告

## 実装内容

共通GBDKランタイム、編集データ、コンパイラ、即時プレビュー、Electronエディターを拡張した。追加フィールドは省略でき、既存作品の縦スクロール、自弾6発、素材の発射点、A+Bボムを維持する。

| 対象 | 追加内容 |
| --- | --- |
| 横ステージ | 幅20〜512タイル・高さ18タイル、横列転送、壁判定、スクロール停止・速度イベント・周回・視差、HUD位置との座標変換 |
| 射撃 | 縦方向の編隊間隔、波移動の振動軸、左へ向かう誘導弾、武器別発射点、自弾上限1〜24、斉射単位の弾枠確保 |
| アイテム | イベント、敵とBGからのドロップ、ショット・速度・ボム・残機・得点を組み合わせた取得効果、上限、一回だけの適用 |
| 強化 | 初期段階を含むショット・速度表、ミス時の維持／低下／初期化、ステージ間の保持、新規プレイでの初期化 |
| 破壊BG | 16×16・最大512個・HP1〜15、得点・ドロップ・接触判定、重複禁止、下地への復元、ミス・周回・画面再読込後の状態保持 |
| 編集 | 横マップ、BGスタンプ・消去、アイテムとドロップ、強化段階、Undo／Redo、PNG保存・再読込、複製、プレビュー、診断からの選択 |

通常ショットの破壊判定はROM上の16ピクセルセル索引を参照する。全物体を毎ショット走査しない。HPは256バイト、描画更新待ちは64バイトに圧縮し、通常更新は最大2物体・8タイルずつ転送する。短い周回面では、1物体の複数の表示位置を消すために8タイルを使う場合がある。先読みされた画面外の複製も消去する。HPが0になった時点で加点・ドロップを確定するため、後続ショットやボムで二重加点しない。画面全体の再読込では保持したHPから描き直す。

アイテムは既存39エンティティのプールを使い、定義した作品では最大4個分の生成枠・OAMを予約する。破壊BGはエンティティとOAMを使わない。変更しないBG弾描画マスク272バイトをROMへ移し、スタック1024バイトの予約検査を維持した。

計測に基づく最適化として、空の描画更新待ちを走査しないカウンター、直前に参照した物体IDのキャッシュ、通過可能BGだけの面における16ピクセル単位の検索を追加した。壁と物体が混在する面は元のセル順序を保つ。旧作品用の単発生成とBG弾ボス画面の処理も維持する。

## サンプル

`projects/side-caravan`は独立した編集可能作品で、新規作品テンプレートとWindows配布用テンプレートへ登録した。通常ビルドは保存済みJSON／PNGを使い、初期制作スクリプトで再生成しない。

- 宇宙施設への接近→戦艦甲板→炉心区画→3段階のTRIPLE CORE。道中10,800ゲーム更新、ボス撃破でクリア。
- A連射、B押下でボム、STARTでポーズ。初期3機・ボム2個、各上限9。復帰時ボム2個。
- 通常→2連→3方向→5方向。移動速度1.5／1.75／2／2.25ピクセル／更新。ミスでショット1段階低下、速度維持。
- P・速度・ボム・1UP・500点の5種類を配置。281個の破壊BGと、各64個の密集区間3か所。全敵・ボス・BG・得点アイテムの通常合計上限34,320点。
- 原画22枚の4色PNG、オリジナルの機体・敵・施設・タイトル・演出。BGMは既存オリジナル曲から選曲。出典とライセンスは[素材説明](../projects/side-caravan/assets-src/README.md)に記録。

操作と制作手順は[サンプル説明](../projects/side-caravan/README.md)、共通機能は[編集方法](horizontal-stg.md)を参照。

## 検証の区別

通常ROMの通し試験は、改造・無敵化・時間短縮を行わず、読み取りと通常のコントローラー入力だけで進行する。実際にミスする入力も含める。別の短縮テスト作品では512個の境界、周回、上限、同時命中などを集中的に検査する。両者の結果を混同しない。

ゲーム内時間は60更新を1秒とする。負荷が高い区間ではゲーム進行が遅くなるため、180秒の道中が実時間180秒で終わるという意味ではない。性能値は表示フレーム／ゲーム更新で示し、常時60Hzの保証とはしない。

## 通常ROMの通し結果と負荷

最終ReleaseそのものをBoytacean 0.13.2のDMG通常速／CGB倍速で実行した。入力操作だけで道中からクリアまで進み、両機種とも14,265ゲーム更新・31,340点でクリア。全5種類のアイテムとショット・速度の最終段階、3ボスフェーズ、1回の実際のミス、8回のボム、ポーズ、再起動後のSRAMランキングを確認した。残った4物体はこの入力経路で撃ち漏らしたもので、通常全破壊の得点上限を得た試験ではない。

フレーム間隔の集計は14,141更新で、ポーズ・画面遷移・ボム中を除く。ボム欄には画面差し替えと復元を含む。通常破壊の待ちは更新完了後に測り、同じ更新内で消去された分は0となる。大量同時破壊の8タイル上限と待ちの保持は別の短いループ試験で検査した。

最適化の原因調査には、初期5方向・無敵時間1024へ変更した別の診断作品を使用した。120〜360更新の同一入力で、最適化前→後の平均はDMG 2.921→2.130、CGB 1.792→1.100フレーム／更新。この比較は最終の短いループ修正・HUD分岐最適化・バンク移動前の局所計測であり、上表の通常ROMとは区別する。

## 性能ゲートの未達と未確認事項

旧性能ゲートの数値は緩めていない。既存stress試験は基準DMG 2.9／CGB 1.85に対し、変更前HEADの再ビルドでも2.917／1.862で不合格だった。今回のHUD最適化後の診断ROMは2.935／1.887で、HEADより約0.63％／1.34％遅い。各機種720状態のC／プレビュー照合とHEADとの状態ハッシュ一致は通るが、この性能目標は未達として残す。

既存の比較ROMを関数境界で読み取り計測したところ、入力・カメラ・衝突フラグ、敵、プレイヤー衝突、弾の分岐に合計約1,400 Tcycles／更新の追加コストがあった。通常更新に新しい地形API呼出しはなく、OAMやゲーム状態の差もない。小さなCPU時間差がVBlank待ちの境界を越えることが残差の原因で、未検証の追加最適化は最終ROMへ入れていない。

既存BG弾64発試験の「CGBで毎更新1表示フレーム」という条件もHEADで不合格。追加HUD判定による悪化は修正し、DMG 3.0／CGB 1.75フレーム／更新、512更新の区間別推移はHEADと一致した。画素・当たり判定・OAM・VBlankの検査はPASS。ほかのanimation、enemies、boss-0／1／2の5ケースは両機種で既存ゲートに合格している。旧性能比較は低頻度処理の最終バンク移動前の診断ROMによる。

BGBは最終SIDE／STAR ROMで確認。SIDEはDMG 2,522更新、CGB 3,955更新まで通常入力を再生し、横カメラ、強化、得点、Bを保持した区間ごとの1個消費を確認した。通しクリアの証拠は上記Boytaceanによる。

Emuliciousは最終SIDE／STAR両方でCLI起動とDAP接続を試みたが、読取り評価が`platform.debugger.DAPDebugger.evaluate`の`NullPointerException`となった。接続成功だけを起動・ゲーム動作の確認とは数えていない。Emuliciousでの実行、人による操作感・聴感、実コントローラー、DMG／CGB実機の液晶・保存・音は未確認。タイトルの非ゼロPCMと道中・ボスのBGM選択は自動検査済み。

## 再現コマンド

```bat
doctor.cmd
clean.cmd hello-gb
build.cmd hello-gb -Configuration Debug
test.cmd
build.cmd star-caravan -Configuration Release
build.cmd side-caravan -Configuration Debug
build.cmd side-caravan -Configuration Release
.tools\node\node.exe editor\tests\horizontal-ui-run.mjs
.tools\node\node.exe editor\tests\project-ui-run.mjs
.tools\node\node.exe editor\tests\side-caravan-play.acceptance.mjs projects\side-caravan\build\Release\side-caravan.gb .cache\side-final\play --exercise-miss
.tools\node\node.exe editor\tests\side-caravan-native.acceptance.mjs projects\side-caravan\build\Release\side-caravan.gb .cache\side-final\bgb
```

`test.cmd`は作品のビルドフォルダーをcleanするため、Releaseの作成と最終ROMの検査はそのあとに実行する。エディターの`test:core`／`test:rom`／`test:horizontal-ui`／`test:side`／`test:side:native`からも専用試験を実行できる。
