# STGエンジンの最適化と検証

このページは2026-09-09時点の24発版の記録です。現在の32発・敵12機版とROM解析、CPU計測については[2026-09-10の調査結果](stg-performance-investigation.md)を参照してください。以下の再現コマンドは当時のリビジョンを対象にしています。

## 実装

敵弾の種別上限を16発から24発に拡張しました。合計31オブジェクトとOAM40個の空きが必要な点は変わりません。エディターのシミュレーターも同じ上限を使います。既存作品は共通エンジンで再ビルドすると適用されます。

- **描画**：8×8・1タイルの弾は専用経路でOAMへ書き込みます。複数タイルのキャラクターは既存のSM83メタスプライト処理を使います。画面端・HUDとのクリッピングと描画順序は共通です。
- **描画準備**：非再入の描画コンテキストを使い、各スプライトで5引数を渡す処理を廃止。HUD上下境界も描画呼出しごとに一度だけ計算します。
- **素材・アニメーション**：素材情報をSM83上で16バイトに整理。重複していた当たり判定情報を除き、周期をビルド時に計算します。フレーム数と均等な表示時間がともに2の累乗ならシフト・マスクを使用し、それ以外は従来と同じ周期演算を使います。
- **移動・当たり判定**：敵更新の作業変数を非再入の静的領域へ移し、スタック参照を削減。当たり判定用座標を作る関数は4引数から2引数へ変更。縦方向を先に判定し、自機弾または攻撃対象が存在しない場合は組合せの走査を省略します。
- **コンパイル**：Debug/ReleaseともSDCCのレジスター割当て探索量を`--max-allocs-per-node 50000`に設定。ROM内の処理を軽くする代わりにビルド時間は増加します。

Q4座標、負数のゼロ方向への丸め、弾の速度・軌道、判定範囲は維持しています。静的作業領域を使う関数はメインループ専用で、割込みから呼びません。完成OAMのVBlank転送待ちやブラウザーの表示周期制御は削除していません。

## 調査した手法と選択理由

GBDKの公式指針にある、小さい整数型、定数の事前計算、ポインターの前進、引数とスタック参照の削減、生成コードと実測による判断を適用しました。乗除算・非2累乗の剰余はSM83上ではソフトウェア処理になります。[GBDK Coding Guidelines](https://gbdk.org/docs/api/docs_coding_guidelines.html)

固定長プール、弾速テーブル、直線移動の加算更新、メタスプライト内部のアセンブラ化は既存実装に含まれています。今回の効果には、それらの導入前との差を含めていません。空間分割は今回の自機弾6・攻撃対象最大9という規模では追加管理が必要になるため未採用です。波・往復・経路移動の全面的なテーブル化も今回は行っていません。

40個のOAMと1走査線10個の制限はCPU最適化で増やせません。OAMの選択はY座標と順序に依存するため、生成可能な弾数と、欠けずに同時表示できる弾数を区別します。[Pan Docs: OAM](https://gbdev.io/pandocs/OAM.html)

## 測定条件

- 比較元：`625c3a04c3fe7be5d2d78288649ea997bf07c5b2`。
- GBDK 4.5.0 Linux版、Boytacean 0.13.2、DMG通常速／CGB倍速。
- 実際のROMを実行し、ゲームRAM・入力履歴・エミュレーター速度は改変しません。
- 通常戦闘はNOVA SPEARの元データでAを保持し、120～600、600～1200、1200～1800 tickを測定。これは全編クリアの証拠ではありません。
- 高負荷・ボス試験は独立した検証用プロジェクトです。高負荷は3機の固定敵による扇状弾。ボス試験は登場動作を維持し、HPによるフェーズ切替だけを180 tickの時間切替にして全フェーズを通します。無敵時間は1024 tick、計測は120～720 tickです。
- 高負荷の公平な速度比較には、比較元のコピーで敵弾上限だけを24にした対照ROMも使用します。この対照ROMを製品版として配布しません。
- 更新入口の実行アドレスで停止し、直前に完成・転送されたOAMと状態を毎回検査。各ケース・機種で720更新を検査し、そのうち600区間を測定します。CPUサイクルを1表示周期の予算へ換算し、PPUフレーム差も別途記録します。ホストPCの処理秒数はGBのFPSとして扱いません。

生の集計、ROMハッシュ、状態ハッシュは[測定結果JSON](stg-performance-results.json)にあります。

## 結果

### 通常戦闘：元のNOVA SPEAR

数値は論理更新/秒です。背景のスクロール量や敵の数を測定中だけ減らしていません。

| 機種 | tick区間 | 変更前 | 変更後 |
|---|---|---:|---:|
| DMG | 120～600 | 26.59 | 34.21 |
| DMG | 600～1200 | 27.27 | 32.94 |
| DMG | 1200～1800 | 28.88 | 34.83 |
| CGB | 120～600 | 46.69 | 51.84 |
| CGB | 600～1200 | 49.50 | 54.55 |
| CGB | 1200～1800 | 55.73 | 59.14 |

DMGで約21～29%、CGBで約6～11%改善しました。各施策の段階測定もJSONへ収録しています。

### 高負荷：24発同士の比較

| 機種 | 上限だけ24にした比較元 | 最適化後24発 | 改善率 | 更新間の最大PPUフレーム差 |
|---|---:|---:|---:|---:|
| DMG | 12.36 | 15.76 | 約28% | 5 → 4 |
| CGB | 21.09 | 29.86 | 約42% | 3 → 2 |

元の16発上限では同じ試験がDMG 15.57、CGB 29.86更新/秒でした。最適化後は50%多い24発をほぼ同じ速度で処理しています。24発の処理・OAM配置を確認しましたが、密集時は最大22スプライトが同じ走査線へ重なるため、表示の欠けは残ります。常時60更新/秒を保証する結果ではありません。

### ボス：同じ条件での比較

| 機種 | ボス | 比較元 | 最適化後 |
|---|---|---:|---:|
| DMG | TRIDENT | 29.76 | 32.75 |
| DMG | BASTION | 30.47 | 32.40 |
| DMG | HELIX | 31.85 | 33.87 |
| CGB | TRIDENT | 59.42 | 59.72 |
| CGB | BASTION | 59.32 | 59.72 |
| CGB | HELIX | 57.98 | 59.72 |

高負荷と3ボスの全8比較で、各720更新の状態・敵弾座標・HP・フェーズ・生成見送り数・OAMの連続ハッシュが変更前後で一致しました。均等8/128 tickと不均等3/7/11 tickのアニメーションも、DMG/CGBで各720更新のOAMとシミュレーター一致を検査しています。

静的WRAMとシャドウOAMの合計は高負荷試験で1962 → 2046バイト（+84バイト）。NOVA SPEARのROM容量は128 KiBのままです。

## 再現手順

固定されたツール環境をセットアップし、エディターをビルドしてください。Windowsでは`node`を`.tools\node\node.exe`に読み替えられます。

```sh
npm --prefix editor run check
node editor/tests/performance.mjs projects/nova-spear/build/Release/nova-spear.gb .cache/performance.json
node editor/tests/stg-benchmark.mjs . .cache/stg-performance stress --expect24
node editor/tests/stg-benchmark.mjs . .cache/stg-performance animation --expect24
node editor/tests/stg-benchmark.mjs . .cache/stg-performance boss-0
node editor/tests/stg-benchmark.mjs . .cache/stg-performance boss-1
node editor/tests/stg-benchmark.mjs . .cache/stg-performance boss-2
```

別チェックアウトの比較元も同じスクリプトへ渡せます。`--dense-baseline`はコピーした旧エンジンの16発制限だけを24へ変更します。`--reuse`は同一の検証用ソースとROMハッシュを確認した上で再測定します。診断ROMは出力フォルダー内に作られます。

Windows CIにも5ケースのDMG/CGB検証と測定JSONの保存を追加しています。BGB・Emulicious・実機での結果は、WASMエミュレーターの結果と分けて扱ってください。実機上の性能・互換性は本測定では未検証です。
