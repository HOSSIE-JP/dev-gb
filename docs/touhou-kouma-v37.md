# 東方 紅魔巡礼 GB v0.37 — 追従光線と弾幕の追加

魔理沙の通常・低速射撃を、自機のX座標に追従する長い貫通光線へ変更しました。先頭へ飛んでいく弾の列ではなく、自機Y-8の発射口から画面上端までつながる棒状の光です。幅2pxの芯を残して周囲の4pxの光を交互表示します。Aまたは低速のBを離すと消えます。通常は8更新ごとに1ダメージ、集中は10更新ごとに2ダメージです。霊夢の幅広いショットは維持しています。

## 描画とメモリ

- 光線を使う作品では、全OBJをGB標準の8×16単位で描画します。16×24の自機は6→4 OAM、24×24のボスは9→6 OAMになります。原画の寸法・原点・アニメーション・当たり判定はそのままです。
- タイルは縦2枚を対にして再配置し、8pxだけ余る最下段は透明で埋めます。GBCは対になる2枚に共通のパレットを割り当てます。
- 光線は常駐4タイルを繰り返し、最大9 OAMを予約します。弾エンティティの移動・寿命更新・毎フレームのVRAM転送は追加しません。ダメージ周期にだけ敵・ボスの矩形と縦線を調べます。
- 本作のOBJ領域は126／128タイルです。増えた弾幕・経路データをROM0へ置くため、ゲーム更新をまとめて別のROMバンクで実行します。入口・ISR・共通ヘルパーは固定領域に残し、敵1体ごとのバンク切替は増やしません。
- 光線のない作品は従来の8×8形式です。OAM全体40個・同じ走査線10個の制限は残ります。[ハードウェア仕様](https://raw.githubusercontent.com/gbdev/pandocs/master/src/OAM.md)

## 敵とボス

道中には既存の妖精・蝙蝠・魔導書の画像を使い、斥候、左右の切り返し迎撃、左右の急降下、横滑り砲台、精鋭狙撃、追尾魔導書の8行動種を追加しました。6つの新しい射撃設定により、遅い置き弾・狙い三連・散弾・速い狙撃・短時間の誘導を使い分けます。3面から段階的に導入し、序盤2面と無武装の8体ラッシュは残しています。

ボス用パターンは21→42種類です。各ボスの3モードへ固有の補助攻撃を1種類ずつ追加し、従来の下方向の広域弾と組み合わせます。自機狙い扇弾をエンジン／エディターへ追加しました。上に回り込んだ自機も狙い、扇の中央には必ず狙い弾を含めます。ボスの移動は全21モードで継続する経路へ変更しました。往復、上下の切り返し、斜め移動、八の字風の経路をモードごとに使い分けます。

HP100×3、各60秒、12→40発のステージ別同時弾数上限は維持しています。既存の広域弾は発射間隔を少し広げ、寿命を160更新へ調整して補助攻撃を入れる余地を作りました。「2倍」は攻撃の種類であり、同時弾数ではありません。

移行の正本は `projects/touhou-kouma/touhou-kouma-design/v37-gameplay/apply.cjs` と `brief.json`。既存PNG・BGM・背景・スコア・セーブ識別子は変更していません。

エディターの弾幕設定には「自機Xに合わせるレーザー」「自機狙い扇弾」を追加しました。光線は「間隔」でダメージ周期、「ダメージ」で1回の威力を編集します。選択対象プレビューでZを押すと確認できます。光線で使わない弾速・角度・発射位置などの欄は隠し、タイル使用量には光線と低速マーカーの予約分も含めます。

## 検証結果

- Debug／Releaseとも成功、ROMは同一の2MiB。コンパイラー警告0件、静的WRAM＋shadow OAMは7,163バイト、スタック予約は1,024バイト以上です。
- `test.cmd hello-gb` はTypeScriptと163件成功。`star-caravan` のDebug／Releaseも成功し、ROM・統合・BGBの追加4件が成功しました。こちらには既存の最適化／到達不能コード警告が各構成4件あります。
- 製品ROMを通常のメニュー入力で操作し、GB／GBCそれぞれで全7ボス×3モードの移動、HP変化、クリア演出への到達を確認しました。追従・射撃・ボムを使う自動操作であり、通常キャンペーンの通しクリアではありません。
- GB／GBCとも、全7ボスの上に自機を移動すると狙い弾が上方向に発射されました。上端の全座標を網羅した安全地帯不存在の証明ではありません。
- ビームの芯が全長につながること、左右追従、射撃解除、集中射撃、ボスへのダメージ、8×16の全常駐画像と透明パディングを検査しました。自機の登場無敵点滅が終わった画像でも確認しています。
- 別途、通常の `ce_step` を通る衝突専用ROMで、6つのエンティティスロットと縦横の境界位置、発射口の上下を計1,080条件／機種で検査しました。これは製品ROMの全敵配置を網羅する検査とは分けています。
- 両機体の低速マーカー、道中／ボスのボム、常駐スプライトの保持、背景切替・スクロール・HUDをGB／GBCで確認。霊夢ボムは17,280画素×4条件の原画比較で欠損0でした。
- Electronの実際のUIで、新しい光線・扇弾の選択、プレビュー、間隔の編集と保存・再読込を確認。既存のボス、会話、機体別画像、エンディング、右HUDの操作も回帰確認しました。検査には一時プロジェクトを使い、本作の値は変更していません。

長い道中検査で、追加した敵の退場経路が画面外の管理マージン内で止まる問題を検出しました。退場先を消去範囲の外へ延ばし、無射撃でも全追加種が320更新以内に退場する検査を追加しています。以下はその修正後の数値です。

## 負荷測定

BGB 1.6.6に、v36と同じ5,000表示フレーム分の入力を再生しました。7面・魔理沙の通常射撃、道中／BOSS SELECTの2経路です。入力列のSHA-256も一致しています。値はゲーム更新／秒であり、描画フレーム数やホストPCの実行速度ではありません。

| 機種・経路 | v36 | v37 |
|---|---:|---:|
| GBC・道中 | 49.32 | 56.40 |
| GBC・ボス | 54.33 | 56.80 |
| GB・道中 | 29.10 | 35.50 |
| GB・ボス | 25.83 | 28.51 |

敵の構成、武器、弾数、被弾する時刻が変わるため、純粋な描画方式だけの速度比較ではありません。両版で開始時刻・更新数が一致した区間だけを抜き出しても、GBC道中50.21→56.53、ボス54.65→57.01更新／秒でした。区間の一覧を検証JSONに保存しています。

同じ1,200更新を調べるBoytaceanのCPU測定では、`ce_step` の平均Tサイクルが道中63,673→44,234、ボス65,312→54,136でした。割り込みを含み、描画は含まない値です。長い道中測定では追加敵の蓄積による持続的な低下が解消しました。

GBCボスのVRAM DMAは1,498サンプルすべてVBlank内で終了し、最大終了LY=151、余分なVBlank待ち0回でした。この性能経路のBG弾数ピークはv36の28発、v37の18発であり、40発固定負荷試験ではありません。全ボス進行検査での最大観測値は25発です。

常時60fpsは達成していません。GBC道中の120更新区間には約44更新／秒まで落ちる箇所があり、実機の表示・操作感、音の聴感、長時間展示、通常キャンペーン通しクリアは未検証です。Emuliciousは最終ROMの起動・接続まで試しましたが、DAPの値取得が `NullPointerException` で失敗したため、プレイ検証済みとは扱っていません。
