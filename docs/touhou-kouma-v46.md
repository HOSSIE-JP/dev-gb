# 東方紅魔 STG v46 — GBC専用出力と最新内容の照合

v45のゲーム内容と、新規16曲のUGE音楽統合を維持し、正規エディタと標準ビルドの通常出力を `touhou-kouma.gbc` に統一した。版付き出力は `projects/touhou-kouma/build/{Debug,Release}/touhou-kouma-v46.gbc`。

以前の `.gb` は拡張子が紛らわしかったが、v45・音楽統合後ともヘッダー `0x143 = 0xC0` のGBC専用ROMだった。今回はプロジェクトの出力名をエディタのビルド昇格・プレビュー読込みにも適用し、古い `.gb` を誤って読まないよう修正した。GBC専用ヘッダーが違えば標準スモーク検査が失敗する。

「ROMを書き出す」の既定名・ファイル種別も生成ROMの拡張子を引き継ぐ。最後にこのダイアログ設定を変更した後、エディタ再ビルド・型検査を追加で実行して合格した。書出しダイアログを手動操作する検証は未実施。

## 内容の保全

v45のGit基準 `0160bd7` と比較した。音楽設定・曲割当・音楽インポート情報を除くゲーム設定は一致し、既存7ステージの順序、2枚のロゴ、400フレームの動画を保持している。元画像204ファイルのSHA-256はすべて一致する。主要処理10ファイル（flow/movie/render/sprites/special/boss-phase/bg-bullets/terrain/items/save）もv45から変更していない。曲の置換を除き、ゲーム内容を旧版へ戻す変更はない。

旧v45 ROMおよび既存出力は検査前に `.cache/gbc-v46/before-roms` に保全した。提供済み `bgm_v2.zip` とプロジェクト内キャッシュは変更・コミットしない。

## 検証

- 正規Electronエディタで16曲の選択、割当の変更・保存・再読込み・復元、既存リザルト曲の編集・保存・Undoを実行。Debug／Releaseの実ビルドが `.gbc` を生成することを確認した。
- 完成ROMの起動操作16ケース、動画400/400フレームの画素一致、動画のスキップ・タイトル復帰・通常開始を再検証。動画の超過は0、PCMブロック数は10,287。
- BGBでロゴ送り・自然動画終了・再プレイの3ケースを再実行して合格した。
- 非GBC専用ヘッダーを検査用コピーに設定し、標準スモーク検査が拒否することも確認した。
- 音楽統合時の実ゲーム14道中／ボス経路、タイトルのループ、効果音・ポーズ・死亡・復帰・コンティニューの証拠は、今回ROMのSHA-256が同一であることを確認して引き継ぐ。16曲すべての長時間ループ検査は別の診断ROMであり、実ゲームの全編プレイを意味しない。

Debug／Releaseとも4,194,304 bytes、GBC専用ヘッダー `0xC0`。SHA-256は `4bf64e8aa3e85f6401fd98d3b977adc3d7167dbfcccb1dbe4fa7af93e05b99bb`。出力名の修正でゲームのバイナリは変化していない。

標準コマンドの最終結果は `projects/touhou-kouma/touhou-kouma-design/qa-v46.json` に記録する。生ログと詳細照合は `.cache/gbc-v46`、音楽検証の詳細は `docs/touhou-kouma-uge-bgm-v2.md`。

## 未検証と制限

Emuliciousには接続できたがEvaluateRequestがNullPointerExceptionで失敗し、実行検証は成立していない。全7ステージを連続クリアする人間のプレイ、試聴による音楽品質判断、GBC実機は未検証。従来の表示期限超過や処理落ちが解消されたとは主張しない。ユーザーが感じた拡張子以外の具体的な症状は、指摘箇所が判明した時点で追加の照合対象になる。
